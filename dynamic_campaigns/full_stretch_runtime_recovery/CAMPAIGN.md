# Full Stretch Runtime And Binary Recovery Proof

## Goal

Produce a canonical green proof bundle showing that MCP Factory supports files,
installed paths, directories, repos, scripts, Windows binaries, contracts, SQL,
JSON-RPC, SOAP, REST, LDAP/JNDI, CORBA ORB/IIOP, controlled RPC, controlled
remote DCOM, and evidence-ranked undocumented binary recovery.

Every required proof must include generated schema, GPT `tool_call`, backend
`tool_result`, transcript, and downloadable artifacts.

## Campaign Start Packet

- `wider_goal`: truthfully hit sponsor stretch goals with runtime-backed or
  evidence-ranked proof.
- `current_frontier`: extend the proof contract, then replace the remaining
  shaped hard legacy proofs one by one.
- `stop_gate`: latest full Sponsor Demo E2E green with stretch proof matrix
  passing and public docs/UI pointing to that run.
- `dominant_blocker`: hard runtimes require real protocol/runtime artifacts, not
  prior adapters.
- `expected_delivery_or_proving_target`: `sponsor-demo-e2e` artifact containing
  `final-summary.md`, `final-summary.json`, `sponsor-report.html`,
  `runtime-mode-matrix.json`, `stretch-proof-matrix.json`, transcripts, schemas,
  service logs, Ghidra evidence, and Windows proof logs.
- `delegation_authorization`: absent; keep work local unless user explicitly
  authorizes subagents.
- `operator_constraints`:
  - `time_budget`: long-running campaign; use focused workflows before full VM
    runs.
  - `merge_or_push_expectation`: commit and push only after tranche writeback and
    local checks.
  - `allowed_risk_level`: controlled fixtures and temporary Azure resources are
    acceptable; do not destabilize the current green path.
- `required_outputs`: prompts, tranche summaries, evaluations, dispatch
  accountability, architect briefs, blocker writebacks, and final closeout.

## Tranches

1. `001-proof-contract` (`trust_or_setup`): make final reports understand
   stretch proof fields while preserving baseline green compatibility.
2. `002-ldap-runtime` (`bounded_fix`): prove LDAP/JNDI through a real
   LDAP-compatible runtime.
3. `003-corba-orb-runtime` (`bounded_fix`): prove CORBA through a real ORB/IIOP
   controlled fixture.
4. `004-msrpc-runtime` (`bounded_fix`): prove RPC through controlled MSRPC or
   Windows RPC fixture, not XML-RPC.
5. `005-remote-dcom-runtime` (`bounded_fix`): prove controlled remote DCOM from
   a distinct remote context.
6. `006-ghidra-binary-recovery` (`bounded_fix`): prove evidence-ranked recovery
   from undocumented compiled fixtures using Ghidra plus dynamic probing.
7. `007-expanded-repo-windows-proof` (`bounded_fix`): expand repo proof and add
   a deterministic compiled Windows runtime fixture.
8. `008-ui-video-proof-mode` (`bounded_fix`): add video-ready loaders and proof
   badges.
9. `009-final-canonical-green` (`authoritative_validation`): run focused
   workflows, full Sponsor Demo E2E, parse artifacts, update public pointers,
   then write closeout.

## Non-Negotiable Boundaries

- Do not claim arbitrary enterprise estate support.
- Do not claim perfect arbitrary closed-source binary semantic recovery.
- Do not silently downgrade MSRPC, CORBA ORB, LDAP, or remote DCOM to prior
  runtime-shaped proofs.
- Deallocate or delete temporary Azure resources and record cleanup artifacts.
